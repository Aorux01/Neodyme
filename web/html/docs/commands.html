Console Commands

Commands are entered in the server terminal. All commands start with /.

General

CommandDescription
/help [page]List available commands (paginated, 10 per page)
/versionShow server version
/uptimeShow server uptime
/memoryShow heap memory usage
/healthFull health check (memory, tokens, platform)
/readyCheck if all services are operational
/clearClear console and print ASCII logo
/stopGracefully shut down the server

/reload

CommandDescription
/reloadReload config + plugins + shop in one shot
/reload configReload configuration from server.properties only
/reload pluginsUnload and reload all plugins
/reload shopRe-initialize shop rotation

/data - Database Migration

CommandDescription
/data migrate json mongodbMigrate all data from JSON files to MongoDB
/data migrate mongodb jsonMigrate all data from MongoDB to JSON files

Flags:

  • --dry-run - Preview what would be migrated, no data is written
  • --confirm - Skip the confirmation prompt and run immediately
# Preview migration
/data migrate json mongodb --dry-run

# Run with auto-confirm
/data migrate json mongodb --confirm

/test - Test Suite

Checks come in two kinds. Health checks are read-only and also feed the public status page and the Developer panel. Functional checks run real scenarios (sign in, tokens, bans, password reset, two-factor...) on throwaway accounts that are removed afterwards. They never run on their own.

CommandDescription
/test listList the groups and how many checks each one has
/test allRun every health check
/test all --functionalRun health and functional checks
/test <group>Run one group: server, database, account, services, plugins. Functional groups (core, auth, recovery, security) run directly by name.

Functional tests can also be started from the Developer panel, in the System tab. Plugins can add their own checks with TestRegistry.register().

/diagnostic

Prints a full server diagnostic report: OS, CPU, RAM, uptime, database type, active services, token counts, and loaded plugins.

/diagnostic

/give

CommandDescription
/give vbucks <username> <amount>Give V-Bucks to a player
/give item <username> <templateId>Give a cosmetic item to a player's locker

The templateId must include the type prefix and the item ID, separated by :. For example:

/give item Pseudo001 AthenaCharacter:CID_A_248_Athena_Commando_M_ZombieElastic_E
/give item Pseudo001 AthenaBackpack:Backpack_Titanium
/give item Pseudo001 AthenaDance:EID_BoogieDown
/give item Pseudo001 AthenaPickaxe:Pickaxe_ID_010_Lockjaw

Supported item types:

  • AthenaCharacter - Outfits (skins)
  • AthenaBackpack - Back Blings
  • AthenaPickaxe - Harvesting Tools
  • AthenaGlider - Gliders
  • AthenaDance - Emotes
  • AthenaItemWrap - Wraps
  • AthenaSkyDiveContrail - Contrails
  • AthenaMusicPack - Music
  • AthenaLoadingScreen - Loading Screens
  • AthenaBattleBus, AthenaVehicleCosmetics, AthenaPet, AthenaPetCarrier, AthenaSpray, AthenaToy, AthenaEmoji

If the player already owns the item, the command will warn you instead of adding a duplicate.

/caps

Particular authorizations: allow one permission to a single account on top of its role, or forbid one it would normally have. A denial always wins, and owners always have everything. The same actions exist in the Admin panel, Permissions tab, with extra checks that stop staff from raising themselves.

CommandDescription
/caps listList every permission, grouped by panel, with the role that has it by default
/caps show <user>Show the role, the allowed and denied permissions of an account
/caps grant <user> <permission>Allow a permission on top of the role
/caps deny <user> <permission>Forbid a permission even if the role has it
/caps reset <user> [permission]Remove one adjustment, or all of them

Example: /caps grant Pierre shop.edit lets a moderator edit the shop slots without making them a developer. Each change is written to the audit log.

/security

Two-factor authentication for the website. Players turn it on from their Security page with an authenticator app. It protects the website only: the game still signs in with the password.

CommandDescription
/security enableRequire two-factor authentication for staff accounts (moderator and above). Staff without it cannot open the staff panels until they turn it on.
/security disableStop requiring it for staff accounts
/security status [user]Show the policy and who is exposed, or the state of one account
/security disable-user <user>Turn off two-factor on an account (lost phone and backup codes). Written to the audit log, and the player is emailed when SMTP is set up.
/security regen-codes <user>Generate new backup codes. They are shown once in the console and never written to the log files.
/security force-reset <user>End every session of an account and send a password reset link. Without SMTP the link is shown in the console.

/whitelist

Optional server-wide whitelist. When enabled (whitelistEnabled=true in server.properties), only whitelisted accounts can connect - enforced on every login (password, refresh and exchange-code grants). Toggling applies immediately, no restart needed.

CommandDescription
/whitelist set <true|false>Enable or disable the whitelist
/whitelist add <user|accountId>Add an account to the whitelist (accepts a displayName or an accountId)
/whitelist remove <user|accountId>Remove an account from the whitelist
/whitelist listList all whitelisted accounts (flags entries whose account no longer exists)

The whitelist is stored in data/whitelist.json (JSON backend) or the whitelist collection (MongoDB), and can also be managed from the Admin Panel → Whitelist tab.

/sac listList all creator codes with uses and earnings

/email - SMTP

Configure outgoing email (SMTP) and send test messages. The configuration is stored in .env (smtpHost, smtpPort, smtpUser, smtpPass, smtpFrom, smtpSecure).

CommandDescription
/email infoShow the current SMTP config and test the connection
/email create <host> <port> <user> <pass> [from]Configure SMTP and verify the connection
/email deleteRemove the SMTP config from .env
/email test <user|accountId>Send a branded HTML test email to the account's email address
# Gmail example (requires an App Password, not your main password)
/email create smtp.gmail.com 587 you@gmail.com app_password "Neodyme <you@gmail.com>"
/email info
/email test MyPlayer

secure is auto-detected: implicit TLS on port 465, STARTTLS otherwise.
